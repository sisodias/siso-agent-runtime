Great Library of SISO · Agents · Runtime

A small public boundary for a large agent system.

The warehouse grew as an application, laboratory, profile store, orchestrator, and integration surface at once. This extraction does not preserve that accidental shape. It preserves six runtime responsibilities behind an explicit launcher and leaves peer capabilities in their own Works.

JSON config→ profile composer→ argv launcher→ coding-agent host→ events + checkpoints

The internal contracts

Control

Control Core

Owns task state transitions and monotonically ordered runtime events.

Continuity

Session Lifecycle

Writes and restores explicit, versioned checkpoints. It never discovers transcripts.

Attention

Context Manager

Applies a deterministic character budget while preserving complete recent messages.

Observability

Status Surface

Projects runtime state into a stable object for humans, UIs, CLIs, or a future MCP server.

Interface

TUI Contracts

Normalizes a deliberately small set of versioned runtime and tool events.

Identity

Profile Composer

Combines only named files, enforces a byte ceiling, and performs no laptop-wide discovery.

Why one repository?

These packages currently change as one adoption unit and share a single runtime contract. Splitting them today would create release coordination without independent value. The boundaries remain visible so any module can become its own Work later when external adoption, independent ownership, or release cadence supplies evidence for the split.

What deliberately lives elsewhere

Skills and Playbooks are capabilities consumed by agents. Agent Zero is orchestration. Agent Brain and Session Intelligence are shared intelligence. Integrations connect external surfaces. Foundry and Evidence Engines are research systems. None is a child of Runtime merely because the old application happened to contain it.

Honest release boundary: version 0.1.0 proves the public architecture and executable contracts. The warehouse's Pi-specific routing, fleet coordination, raw terminal application, and provider adapters are audited migration work—not features this release pretends to have.

Change without amnesia

MIGRATION-MAP.json records each extraction decision and its reason. runtime.manifest.json exposes the current machine contract. The Great Library assigns stable Work identity independently of this repository, so a future implementation can replace the artifact without rewriting the history of the idea.
